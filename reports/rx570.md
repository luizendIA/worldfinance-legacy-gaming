# RX 570 feasibility report

24 November 2026 · One physical system · D3D11 synthetic rendering and D3D12 capability queries.

| Reference system | Observation |
| --- | --- |
| GPU and driver | Radeon RX 570 Series, 4 GB class. Device driver 31.0.21924.61. DXGI reported 4,272,934,912 dedicated bytes (3.98 GiB). |
| CPU / RAM | Intel Xeon E5-2666 v3 @ 2.90 GHz; nominal 16 GB installed. |
| OS | Windows 10 Pro x64, build 19045. |
| D3D12 | Device creation succeeded at minimum feature level 11_0. Highest shader model returned by this runtime/driver was 6.5. MeshShaderTier was 0 (unsupported). |
| Memory budget | DXGI reported a local process budget of 3,631,994,676 bytes before both profiles in each capture. It can change under load. This is a budget, not a measurement of memory consumed. |

## What ran

A newly written D3D11 scene renders procedural terrain with a vertex/pixel pipeline. A second pass samples the scene texture into a fixed 1280 × 720 output. Four processes alternated native-first and reduced-first order. Reducing each dimension by half cut the intermediate RGBA8 color payload from 3,686,400 to 921,600 bytes. The full-size output remains allocated; tiling, padding, staging and driver overhead are excluded from that calculation.

The median of four run medians fell from **4.343 to 1.505 ms** across the two GPU passes (65.3%). RGB RMSE was **7.613 on a 0–255 scale** against the native image. This deliberately simple scene has no file streaming, presentation, game simulation or CPU-heavy workload. The result measures one resolution tradeoff. [Samples, p95 values and methodology](../benchmarks/README.md)

## What this means for GTA VI

The pinned VIctory README lists SM 6.6 and mesh shaders for its world path. The measured system falls short on both checks. Lowering resolution reduces shading work and intermediate storage; it cannot expose a missing shader stage. Our [indexed fixture](../benchmarks/indexed-rx570/README.md) subsequently passed a synthetic geometry-equivalence test. General shader translation remains open. Switching to Vulkan would require querying features and implementing a compatible algorithm. There is no game compatibility result on this machine. Rockstar lists PS5 and Xbox Series X|S. [VIctory requirements](https://github.com/Marvisak/VIctory/blob/ffe310eb2098e52169f4c44db5ffdabf43a72622/README.md) · [Rockstar release](https://www.rockstargames.com/VI/out-now)

## Next experiments and acceptance criteria

1. Implement a fixed synthetic meshlet and a conventional indexed-draw path. Use the same transforms, indices and winding. Compare image coverage and depth against a CPU reference before comparing timings.
2. Sample local budget and process usage at allocation, after rendering and after cleanup. Stress only bounded allocations with a documented stop threshold. Compare with the calculated texture payload.
3. Test a time-budget controller for dynamic resolution with a fixed camera path, hysteresis and upper/lower scale bounds. Publish per-frame dimensions, timing and image error. Continue to label the two current fixed profiles explicitly.
4. For Vulkan, record adapter, API version, extension and feature-bit results before writing a backend. Compare the same synthetic scene on both APIs. For cache/streaming work, separate cold/warm startup, CPU submission, GPU work and I/O.
